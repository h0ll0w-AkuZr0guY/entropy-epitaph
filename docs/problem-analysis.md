# 问题分析 / Problem Analysis

## 核心问题

互联网产品默认追求永久保存：云端备份、无限历史、永不丢失。它解决了数据遗失，却也让人失去主动告别的空间。废弃代码、结束的关系、失效链接和未完成的梦想长期堆积，既没有被继续使用，也没有被真正放下。

**熵逝碑林 / Entropy Epitaph** 提供相反的数字体验：允许用户为“已经死去”的数字事物举行一次有限、可见且不可逆的告别。

## 反常识洞察 / Contrarian Insight

- 保存不是所有内容的最终目的，有些内容需要一个结束过程。
- 删除通常发生在一瞬间，缺少仪式；永久保存则拒绝结束。
- 持续风化让用户看见时间，而不是把时间隐藏在版本历史里。
- 陌生人的凭吊只延缓消逝，不产生点赞、关注或关系链，避免把哀悼转化为社交指标。

## 目标用户与评审价值

- **个人用户**：纪念未完成的计划、关系、记忆和数字遗物。
- **开发者**：埋葬废弃代码、不会合并的分支和夭折需求。
- **互联网考古爱好者**：保存失效网页的最后快照并见证其再次消散。
- **产品/创意评审**：看到完整、统一且反主流的产品规则。
- **技术评审**：看到真实时间驱动的状态机、调度、AI 降级、三种渲染管线和双部署模式。

## 产品原则

1. 消逝不可逆，只能有限延缓。
2. 所有载体都受熵增约束，包括消逝凭证和档案。
3. 随机性改变路径，但不改变最终结果。
4. 用户应清楚知道公开范围和静态演示的数据边界。
5. 演示数据全部为合成内容，不包含真人隐私、密钥或有效私人链接。

## 风险与处理

- **情绪敏感内容**：产品不诊断、不劝慰，不把 AI 输出包装成心理支持。
- **隐私泄漏**：公共 API 不返回作者、标题或原文，并对可见片段再次遮蔽。
- **不可逆误解**：MVP 明确区分体验规则与数据库运维；演示 fixture 可重置，真实产品需增加确认与保留策略。
- **静态站限制**：GitHub Pages 没有共享数据库；访客操作仅保存在当前浏览器，文档和界面明确标示。
